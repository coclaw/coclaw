Fix mobile inability to pull older chat history when the current session is short. On a chat whose visible content does not overflow the scroll container (e.g. a freshly reset session with only the "New session started" marker), the existing scroll/wheel listeners that drive `__loadMoreHistory` cannot fire on touch devices: a finger pull at `scrollTop=0` produces no scroll event because there is no scrollable distance, and touch screens do not synthesize wheel events. Desktop is unaffected because mouse wheels fire `wheel` regardless of overflow. The fix attaches a small touch handler to the chat scroll container that activates only when the gesture starts at the very top, and on release calls `__loadMoreHistory` if the downward pull exceeded a 60px threshold — independent of whether the content can scroll. Normal touch scrolling is left to the browser (the handler does not preventDefault and only tracks gestures starting at the top), and the existing scroll/wheel paths continue to drive the desktop and overflow-scrollable cases.

In the same change, harden the long-standing weak guard inside `__loadMoreHistory` against mid-load chat switches. The previous `if (!this.chatStore) return` after each `await` could never trigger because the `chatStore` getter is always truthy after a route change — it just resolves to a different store instance. As a result, when a user switched chats while history was loading, the resolved promise would adjust `scrollTop` based on stale measurements taken from the previous chat's view, occasionally jumping the new chat to an arbitrary scroll position. Capture `targetStore` at entry and compare `this.chatStore !== targetStore` (and `__unmounted`) after each `await`, bailing without touching the DOM if the store has changed. Additionally reset `__loadingHistory` in the `chatStore` watcher when switching, so the new chat's `__onConnReady` `scrollToBottom(true)` is no longer suppressed by a residual flag still belonging to the previous chat's in-flight load.
